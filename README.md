# BunnyEra Pay V3.0（中国主要支付渠道基线）

V3.0 将系统范围收口为支付能力，不再扩展商城：统一注册支付宝、微信支付、银联/云闪付三个中国主要渠道；提供 `/api/channels` 渠道状态接口；收银台显示真实配置状态；生产模式下未配置商户号、密钥或证书的渠道会返回 `CHANNEL_NOT_CONFIGURED`，禁止生成假订单或假收款码。支付宝沙箱继续可用，微信和银联在沙箱/模拟模式下仅用于界面及订单流程联调。

V2.1 新增统一视觉系统和独立登录页 `/login.html`：BunnyEra 深色品牌区、响应式登录卡片、安全令牌验证、企业注册入口，以及平台后台统一状态卡片与操作组件。UI 参考 Tabler 的清晰后台结构，但采用 BunnyEra Pay 自有品牌配色和文案。

V2.2 将后台整合为 `/console.html`：工作台、企业与商户、支付渠道、门店与收款码、部门/产品/员工、订单、退款申请、对账报表、CSV 导出与审计日志均在一个响应式运营控制台内完成。旧 `/platform.html` 自动使用新控制台。

V2.3 将企业入驻升级为亚太/东南亚全球商户注册：国家地区与国际区号联动、企业注册号/统一社会信用代码、法人、Gmail 或企业域名邮箱、经营类别，以及营业执照/公司注册证书、门头、室内经营场景三张审核图片。图片仅存储在服务器私有数据目录，单张最大 5MB。

V2.4 新增 `/shop.html` 企业官方店铺：20 个符合经营范围的示范商品、分类、购物车、支付宝/微信订单、个人或企业电子发票资料，并将商品明细和开票信息写入订单。上线前商户应核对实际在售商品、价格、库存和开票类目。

BunnyEra Pay 是 BUNNYERA LLC 旗下的多商户支付管理软件。V2.0 在保留原有收银台、企业档案、门店收款入口、支付宝沙箱和订单对账功能的基础上，新增平台运营层、企业注册申请、商户审核、多商户隔离、部门、产品、员工角色和审计日志。

资金边界：BUNNYERA LLC 提供软件服务，不保管、归集、兑换或代付商户资金；每个商户连接自己名下的支付账户，客户货款由持牌支付机构直接结算给对应商户。平台注册只建立软件档案，真实收款必须另外完成支付机构商户审核和渠道授权。

新增入口：

- 平台控制台：`/platform.html`
- 企业入驻：`/merchant-register.html`
- 商户业务后台：`/admin.html`
- 聚合收银台：`/`

V2.0 平台功能：商户申请提交与审核、独立商户记录、营业执照编号脱敏、部门、产品、员工邀请与角色、审计日志。现有 `catalog.json` 和 `orders.json` 保持兼容；新增平台数据存储在 `data/platform.json`。

V1.5 在同一中国商户主体下增加多品牌、多门店、多收款入口和统一订单对账。长期收款入口允许客户自行输入金额，再生成带金额和订单号的支付宝/微信动态订单。该能力不构成资金清算许可；第三方独立商户入驻时必须使用支付宝直付通、微信合作伙伴/平台产品等官方分账模式。

V1.6 增加“一张营业执照/一个品牌对应一个独立企业档案页”：脱敏营业执照预览、主体资料、支付宝、微信、企业银行卡、虚拟卡、平台账户、钱包、门店、收款入口及该企业订单。资产记录仅允许保存掩码、币种、状态和后台地址，禁止保存密码、验证码、私钥、助记词和完整卡号。

只看效果：直接双击根目录的 `双击查看效果.html`，无需安装 Node.js，也无需启动服务器。

V1.4 已加入 Antom / Alipay Global 美国商户沙箱适配：CNY、`ALIPAY_CN`、`CASHIER_PAYMENT`、RSA256 请求签名、响应验签和支付通知验签。账户激活后填写 `ANTOM_CLIENT_ID`、美国商户网关、商户私钥及 Antom 公钥，并把 `PAYMENT_MODE` 改为 `antom-sandbox`。

独立、零第三方运行依赖的支付系统基线，覆盖电脑网站扫码、手机 H5、后台开单和统一订单查询。V1.1 支持支付宝官方沙箱的电脑网站支付与手机网站支付；微信在沙箱阶段使用本地模拟。真实资金接口仍强制锁定。

## 快速启动

### Windows 一键预览

解压后双击 `start-windows.bat`。首次启动会自动：

- 生成 `.env` 和随机后台令牌
- 生成支付宝 RSA2 应用密钥对
- 打开 `http://localhost:8080`
- 在未填写沙箱 AppID 时自动使用安全模拟页面

支付宝官方沙箱启用步骤：

1. 把 `secrets/alipay-app-public.pem` 中的应用公钥配置到支付宝沙箱应用。
2. 把沙箱 AppID 填入 `.env` 的 `ALIPAY_APP_ID`。
3. 把支付宝平台提供的沙箱支付宝公钥转换/保存为完整 PEM，覆盖 `secrets/alipay-public.pem`。
4. 重新双击 `start-windows.bat`。

应用私钥保留在本机，不上传、不发送。

### 命令行启动

```bash
cp .env.example .env
# 修改 ADMIN_TOKEN，并填写支付宝沙箱 AppID 和本机密钥路径
set -a; source .env; set +a
npm start
```

打开：

- 收银台：`http://localhost:8080/`
- 订单后台：`http://localhost:8080/admin.html`
- 健康检查：`http://localhost:8080/health`

运行测试：`npm test`

## 上线前必须完成

1. 将订单存储迁移到 PostgreSQL/MySQL，并增加唯一索引与审计日志。
2. 微信支付确认商户平台已开通 Native/H5 后，接入 API v3：请求签名、平台公钥验签、AES-GCM 回调解密、查单、关单、退款和账单。
3. 支付宝正式上线时更换正式 AppID、应用私钥、支付宝公钥和正式网关，并增加查单、退款和账单。
4. 回调处理使用事务和幂等键；金额、币种、商户号、订单号全部一致才更新为 PAID。
5. 配置 HTTPS、WAF/限流、集中日志、监控告警、数据库备份和密钥轮换。
6. 完成真实商品页面、用户协议、隐私政策、退款政策、客服入口和虚拟商品交付证据。
7. 在小额测试和对账验收完成前，不启用 `PAYMENT_MODE=live`。

## 下一步需要的非敏感信息

- 微信经营码对应的商户号，以及商户平台内 Native/H5 产品开通状态
- 微信 AppID 类型（公众号/小程序/开放平台）
- 支付宝应用是否已创建、已签约的支付产品
- 正式域名、服务器系统和数据库选择

不要在聊天、截图或代码仓库中提交 API v3 密钥、私钥、证书私钥或支付宝应用私钥。

## 支付宝沙箱配置

1. 在支付宝开放平台沙箱进入沙箱应用，获取沙箱 `AppID`。
2. 生成 RSA2 应用密钥；应用私钥和支付宝公钥保存到服务器受限目录的 PEM 文件。
3. `.env` 填写 `ALIPAY_APP_ID`、`ALIPAY_PRIVATE_KEY_PATH`、`ALIPAY_PUBLIC_KEY_PATH`。
4. `APP_BASE_URL` 必须是支付宝服务器可访问的 HTTPS 地址，否则异步通知无法送达。
5. 沙箱网关保持为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`。

## 宝塔部署

1. 上传并解压项目到独立目录，例如 `/www/wwwroot/yuanpay`。
2. 安装 Node.js 20+ 或 Docker；不要覆盖现有商城目录。
3. 执行 `node scripts/setup.js`，再按支付宝沙箱步骤配置 `.env` 和公钥。
4. 使用 `docker compose up -d --build`，或用宝塔 Node 项目管理器运行 `node src/server.js`。
5. 新建独立域名并反向代理到 `127.0.0.1:8080`，申请 HTTPS。
6. 把 `.env` 中 `APP_BASE_URL` 改为真实 HTTPS 测试域名后重启。

`deploy/nginx.conf.example` 是 Nginx 参考配置。正式部署必须限制 `.env`、`secrets/` 和 `data/` 的公网访问。
